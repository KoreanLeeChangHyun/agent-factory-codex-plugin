본문으로 건너뛰기

명세 문서 읽기와 다이어그램 조사

사람과 AI가 같은 명세를 더 쉽게 읽도록 정보 구조와 시각 표현 원칙을 조사한 비권위 작업 자료입니다.

읽기 전 상태 확인

이 문서는 공식·원저자 자료를 비교해 만든 가공 문서이며, 명세의 권위나 구현 수락을 갖지 않습니다.

자료는 일반 설계 원칙의 근거이지 Agent Factory 사용자를 대상으로 한 연구 결과가 아니며, 웹 문서의 내용과 URL은 이후 바뀔 수 있습니다.

결론

  1. AI 명세를 먼저 목적, 핵심 계약, 작업 선택, 절차, 완료 조건 순으로 정리한다.
  2. 사람용 명세는 같은 내용과 같은 순서·계층을 유지한다.
  3. 하나의 규칙은 권위 있는 위치 한 곳에만 두고 반복 대신 참조한다.
  4. 조사 과정과 채택되지 않은 제안은 명세 밖의 가공 문서에 둔다.
  5. 다이어그램은 관계를 글이나 작은 표보다 명확히 만들 때만 사용한다.

작성 체크리스트

  • 그림이 답하는 질문이 하나인가?
  • 제목에 유형과 범위가 드러나는가?
  • LR 또는 TB 읽기 방향이 일관적인가?
  • 도형·색·선·화살촉의 의미가 일관되고 필요한 범례가 있는가?
  • 관계선에 방향과 구체적인 동사형 라벨이 있는가?
  • 서로 다른 추상화 수준이나 관계 유형을 한 장에 섞지 않았는가?
  • 색을 제거해도 의미가 유지되고 교차선이 과도하지 않은가?
  • accTitle, accDescr, 인접한 텍스트 설명이 있는가?

현재 적용 상태

위 결론은 조사 결과입니다. Human이 수락한 “AI 명세부터 정리하고 사람용 문서를 같은 구조로 동기화한다”는 방향만 실제 명세에 반영합니다. 도형 수, node 수, interactive zoom, Mermaid 이외 renderer는 아직 결정되지 않았습니다.

근거와 출처공식 문서와 원저자 자료
  • Microsoft Azure · Create architecture design diagrams — 방향선, 라벨, 일관된 표기, 범례, 단계적 상세화를 권고합니다.
  • C4 model · Introduction — 혼합된 추상화 수준과 불명확한 관계·읽기 순서를 흔한 문제로 설명합니다.
  • C4 model · Notation — 제목, 범위, 범례, 요소 유형·책임, 단방향 관계 라벨을 권고합니다.
  • Mermaid · Accessibility Options — accTitle과 accDescr의 SVG 접근성 연결을 설명합니다.
  • Notion · Columns, headings & dividers — 세 단계 제목, 제목 기반 목차, 단순 표를 설명합니다.
  • Notion · Customize & style content — 글머리표·숫자 목록과 콜아웃 사용법을 설명합니다.
  • Obsidian · Outline — 제목 계층을 이용한 탐색과 재구성을 설명합니다.
  • Obsidian · Canvas — 카드 그룹과 라벨이 붙은 방향 연결을 설명합니다.
  • Obsidian · Callouts — 본문 흐름 안에서 목록·코드·접기 내용을 담는 콜아웃을 설명합니다.
  • W3C WAI · Complex Images — 복잡한 그림에 짧은 식별과 구조화된 긴 설명을 함께 제공하도록 안내합니다.
  • Graphviz · dot — 방향 그래프의 일관된 배치와 교차선·edge 길이 감소를 설명합니다.
