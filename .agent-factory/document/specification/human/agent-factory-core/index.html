03

핵심 역량과 책임

역량주요 입력생성 또는 관리 정보책임 경계
GatherGoogle Drive, OneDrive, Slack, Notion, Discord 등 분산 출처원본출처 충실성과 provenance를 보존해 프로젝트에 필요한 정보를 동기화합니다. 내용을 조정하거나 스펙 진실로 승격하지 않습니다.
Toolhost, plugin, MCP, project manifest와 외부 provider metadata외부 도구·connector의 논리적 생명주기 제어discovery/catalog, install·update·remove routing, connection/auth, 비밀이 아닌 credential reference, 요청·부여 scope, health, enablement, capability metadata를 관리합니다. 실제 provider 권위를 보존하고 비밀 저장, Agent 실행, Gather sync를 소유하지 않습니다.
Explorer웹, 코드, 문서, 원본과 가공 정보원본 가공분석하고 조사하며 탐색합니다. 원래 자료와 변환 결과를 만들 수 있지만 스펙 문서의 수락·조정 주체는 아닙니다.
InterviewHuman의 지식과 질문가공Main Agent가 현재 대화에서 적응형 인터뷰를 수행합니다. 필요한 배경 조사는 Work가 Explorer 역량을 적용해 수행하고 대화를 재개하며, Explorer는 Human을 사칭하거나 인터뷰하지 않습니다.
Document문서와 근거가 있는 Human 결정원본 가공 스펙세 유형을 정의하고 선택적 provenance 관계를 보존하며 모든 스펙 문서의 Human·AI 표현을 함께 유지합니다.
ConventionHuman이 정한 작업 제약전 단계 통제AI가 따라야 할 제약을 기록하는 약한 하네스로 생명주기 전체에 적용됩니다.
Agent역할, 권한, 맥락, Tool이 준비한 capability, 상태전 단계 실행Work·Verification capability binding, 실행 권한과 receipt를 소유하고 다섯 공학 계층을 통합합니다.
Workspace향후 소유자가 해결할 일정, Agent, Document, 로그, 테스트 source다섯 범주의 Human 관제탑상단 Activity는 일정, 에이전트, 문서, 로그, 테스트 순서의 정확히 다섯 개입니다. Sidebar 구조와 상세 기능은 미결정이며 기반 상태를 소유하거나 실행하지 않습니다.

역량과 public Skill은 같은 분류가 아닙니다. 핵심 역량은 Workspace를 포함한 여덟 개이며 public distributed Skill은 agent, convention, document, gather, tool, workspace 여섯 개입니다. Explorer와 Interview의 지속적 의미·권한 경계는 Convention이 소유하고, Agent의 Work와 Main이 각각 적용합니다. Tool은 Workspace의 여섯 번째 Activity가 아닙니다.

Tool과 Gather의 handshake: Gather는 connector capability, 최소 scope, Human 또는 관리자 승인 필요 여부, 선택 범위를 선언하고 destination·bounded read-only sync·fidelity·identity·provenance·원본문서 산출을 계속 소유합니다. Tool은 실제 부여 scope와 connection readiness를 제공하며 scope를 임의 승격하지 않습니다. Google Drive와 OneDrive의 auth/token 코드는 현재 Gather script에 결합된 관찰 상태이며, 구체적 양쪽 interface와 별도 migration 승인·검증 전에는 이동하지 않습니다.

브라우저 코드의 두 가지 필수 형태

재사용 설치 원본

skills/workspace/assets/browser/

index.html, styles.css, app.js 세 개의 핵심 브라우저 코드와 동반 자산 THIRD_PARTY_NOTICES.txt를 다른 프로젝트에도 설치할 수 있는 패키지 형태입니다.

현재 프로젝트 게시본

.agent-factory/workspace/common/

세 개의 핵심 코드 파일과 동반 notice를 현재 프로젝트에서 실제로 제공하는 byte-identical materialized 설치본입니다.

동기화 경계: 세 개의 핵심 코드 파일과 필수 동반 notice는 두 형태에 함께 존재하고 각각 byte 단위로 같아야 합니다. 패키지 에셋이 재사용 설치 원본이며 common/은 독립적인 두 번째 canonical source가 아니라 현재 프로젝트의 설치본입니다. 한쪽만 바꾸거나 의미 또는 byte가 달라진 상태는 완료가 아닙니다.

serve.py init은 기존 안전한 preflight와 force 규칙을 유지하면서 핵심 브라우저 코드와 THIRD_PARTY_NOTICES.txt를 정확한 대상 프로젝트의 .agent-factory/workspace/common/에 materialize합니다. notice는 attribution과 license 문구를 보존하는 동반 자산이지 네 번째 브라우저 코드 파일이 아닙니다. force가 없으면 다른 설치 파일을 충돌로 처리하고, force가 있어도 다른 일반 common browser 자산만 교체하며 path containment, symlink 방어, atomic copy, launcher 보존 규칙은 약화하지 않습니다.

Document 어댑터 초기화와 물리 마이그레이션

초기화와 물리 어댑터·레이아웃 마이그레이션은 document public Skill 안의 역량이며, 문서의 의미를 분류·변환·조정·수락하는 작업과 분리합니다. 이를 위한 새 public Skill이나 Agent 역할을 만들지 않습니다.

초기화

명시적으로 해결된 어댑터의 호환 물리 구조를 결정론적·멱등적으로 준비합니다. LLM이 필요하지 않습니다.

물리 마이그레이션

어댑터, 레이아웃, locator, 표현 배치를 바꾸되 identity, provenance, authority, pair binding과 documentType을 보존합니다.

≠

의미 Document 작업

분류, 변환, 의미 조정, 수락, 저작은 별도 권한을 가진 작업입니다.

유형 불변식: 물리 마이그레이션은 documentType을 보존하며 Original -> Processed -> Specification 승격을 수행하거나 암시하지 않습니다. 경로·형식 변경만으로 유형이 바뀌지 않습니다.

LLM은 제안·저작에만 조건부로 참여

비실행 제안

Work의 LLM은 legacy 분류·provenance 후보, 어려운 형식 변환, 의미 조정, 두 Specification 표현의 동시 초안을 제안할 수 있습니다. 불확실성은 unknown 또는 requiresDecision으로 남깁니다.

폐쇄형 계획/IR

결정론적 compiler만 version, allowlisted operation·path·identity, precondition, effect, validation, recovery, authority reference를 결속한 계획을 만들 수 있습니다.

결정론적 관리자

현재 상태를 다시 확인하고 필요한 Human 권한이 있을 때만 제한된 초기화·마이그레이션을 수행합니다.

LLM은 lock, hash, copy, move, overwrite, delete, state transition, commit, cutover, integrity 판정, recovery를 제어하지 않습니다. 원시 LLM 출력은 shell·SQL·code·임의 path·wildcard·자유형 tool call을 포함하더라도 절대 실행하지 않습니다. 계획 이후 상태 변경, 알 수 없는 operation, path escape·symlink, 충돌, provenance·authority 누락, 유형 승격, 권한 없는 파괴·cutover, capability·hash 불일치가 있으면 compile·적용·게시·완료를 fail closed로 중단합니다.

두 Specification 표현은 하나의 게시 그룹

한국어 Human HTML/CSS/JavaScript와 AI-facing Skill을 모두 stage하고 의미 정렬을 확인한 뒤 하나의 migration·authoring group으로 게시합니다. 한쪽만 바뀐 결과는 미완료입니다. 어댑터가 pair의 atomic publication을 보장하지 못하면 이전 canonical authority를 유지하고 복구 가능한 staged 상태에서 중단합니다.

실행 그래프와 소유권은 그대로 유지

Main은 Human을 인터뷰하고 권한을 해결하며 orchestration과 결과 통합을 수행하지만 Work나 Verification을 하지 않습니다. Work는 LLM 제안·저작을 수행할 수 있고, 그와 분리된 정확한 권한이 있을 때만 결정론적 실행을 호출합니다. Verification은 근거를 독립적으로 확인하며 fail이면 같은 Work Agent로 돌아갑니다. pass 또는 근거가 있는 Human skip만 graph를 종료합니다. 결정론적 integrity-check는 Verification 역할을 대신하거나 Work의 자기 검증을 허가하지 않습니다.

Gather는 외부 동기화와 document/sync.json, Tool은 connector lifecycle, Agent는 capability binding·실행 권한·receipt를 계속 소유합니다. Workspace는 owner-backed control을 투영·연결할 수 있을 뿐이며 db.sqlite는 비권위 재구축 catalog이므로 manifest, journal, recovery source가 아닙니다.

문서 우선 상태: manager/API, proposal schema, compiled IR, manifest·registry·journal, 실제 command 이름, approval threshold·evidence, backend capability·metadata 요구, pair 정렬 증거, recovery 구현은 아직 구현되거나 완전히 결정되지 않았습니다. initialize, inspect/plan, migrate, integrity-check, recover는 개념적 내부 어휘이며 수락된 CLI spelling이 아닙니다.

미해결 결정

다음 항목은 Human이 결정하기 전까지 목표 구조나 완료 상태로 간주하지 않습니다.

Human 소유

실행 계획과 수락 상태

roadmap 우선순위, deadline, owner, acceptance, risk acceptance, completion state는 이 명세에서 만들지 않았습니다.

Human 소유

다섯 Activity의 상세 정의

일정, 에이전트, 문서, 로그, 테스트의 Primary Sidebar 정보 구조, 상세 기능, 내부 계층, control, metric, source 계약은 아직 결정되지 않았습니다.

미구현

카탈로그 실행 경로

db.sqlite 초기화, authoritative local file scanner, rebuild와 freshness, bounded/sanitized query API, search, runtime dual write의 세부 계약은 이번 schema-only 범위에 포함되지 않았습니다.

미해결

외부 저장소 통합

backend configuration, identity, synchronization/conflict policy, authentication, availability, caching은 아직 결정되거나 구현되지 않았습니다.

미구현

Tool backend와 connector interface

Tool registry/state 저장소와 host·plugin·MCP·project manifest adapter는 선택되지 않았습니다. Tool connection/token lifecycle과 Gather capability/scope request interface도 구현되지 않았으므로 Google Drive·OneDrive auth 코드는 Gather에 유지합니다. credential·token을 저장소나 스펙에 기록하지 않습니다.

미구현·미해결

Document 어댑터 제어면

manager/API 위치와 실제 command 이름, proposal·compiled IR schema, manifest·registry·journal 경로와 형식, identity·hash 규칙, approval threshold·evidence, conflict·cutover 정책, backend capability·metadata 보존, Specification pair 정렬 증거, recovery 구현은 아직 결정되거나 구현되지 않았습니다.
