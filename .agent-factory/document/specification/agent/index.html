01

하나의 실행 그래프

Agent Factory의 역할은 Main, Work, Verification 세 개뿐입니다. Main은 직접 작업하거나 검증하지 않고, 실패한 검증은 같은 Work Agent로 돌아갑니다.

MainWorkVerificationfail → 같은 Work

Verification pass → END

독립 검증이 통과하면 실행 graph가 종료됩니다.

Human skip → END

Human만 authorization reference와 결정 근거를 갖춰 다음 Verification을 생략할 수 있습니다.

Human skip은 graph 전이나 자동 완료가 아니라 근거가 있는 control-plane 의도입니다. 현재 initial 또는 revision Work가 끝난 뒤, 다음 Verification이 시작되기 전에만 적용됩니다. 적용되면 다음 또는 추가 Verification을 시작하지 않고 END에 도달합니다. 이미 실행 중인 Verification을 취소하거나 non-Human이 기록할 수 없으며, 권한 또는 근거가 없으면 fail closed로 거부합니다.

04

Agent가 소유하는 로컬 카탈로그

.agent-factory/db.sqlite의 init·rebuild·status·Agent/Document search·atomic publication·last-good recovery·schema evolution은 Agent 책임입니다.

명령계약
init현재 v3는 변경하지 않습니다. 지원하는 v1·v2는 이전 행을 옮기지 않고 권위 있는 Agent·Document 파일에서 v3로 자동 재빌드하며, created·migrated·unchanged 결과와 원본·대상 버전을 알립니다.
rebuildbounded source를 별도 DB에 구성하고 integrity·foreign key를 확인한 뒤 atomic publication
statusread-only integrity·schema version 3·sidecar·count·FTS5 확인
search-agents / search-documentsparameterized literal Unicode query와 bounded deterministic JSON

python3 skills/agent/scripts/catalog.py --project-root <target-git-root> <command>로 실행합니다. 하이픈과 한국어 token, quote escaping, final-token prefix, 파일당 256 KiB와 rebuild 전체 8 MiB cap, symlink 거부를 유지합니다. DB와 sidecar는 ignored generated artifact이며 권위 있는 Agent runtime이나 Document source를 대체하지 않습니다.

자동 마이그레이션은 카탈로그 행을 신뢰하거나 변환하는 데이터 마이그레이션이 아닙니다. 버전 표식이 없거나 해석할 수 없고, 지원하지 않는 과거 버전이거나 미래 버전이면 기존 DB를 교체하지 않고 명확히 실패합니다. 재빌드·검증·게시 중 어느 단계든 실패하면 이전 DB 바이트를 보존합니다. Workspace는 향후 Agent가 제공하는 read-only 결과를 표시할 수 있을 뿐 직접 초기화·rebuild·status·검색을 실행하거나 카탈로그를 소유하지 않습니다.
