가공문서개요와 explorer/tree

스펙문서는 UI label이며 논리 type은 Specification입니다. 원본문서 개요는 간결한 content 영역을 직접 사용하고 editor header를 표시하지 않습니다. 문서 Sidebar에서는 마지막 스펙문서 그룹의 연결 대기 문구 아래에 끝 구분선을 표시하지 않되 세 그룹 사이의 구분선은 유지합니다. 이 화면 표현은 아직 결정되지 않은 개요 내용 자체를 정의하지 않습니다.

03

원본문서 검색

위쪽 탭과 넓은 카드 없이 12px 안쪽 여백을 유지하는 간결한 VS Code형 표 화면입니다. 로컬에 고정한 Tabulator 6.5.2를 사용합니다.

순서표시 이름동작
1문서 분류정렬·열 필터
2출처실제 inline SVG와 보이는 provider 이름, 정렬·열 필터
3태그정렬·열 필터
4문서 이름header가 아닌 각 cell만 source Original 링크, 정렬·열 필터
5확장자정렬·열 필터
6수정 일자정렬·열 필터

보이는 여섯 metadata field 전체를 대상으로 하는 접근 가능한 전체 검색 입력이 있고, 입력은 code나 markup이 아니라 literal text로만 비교합니다. fitColumns와 content에 맞춘 열별 widthGrow 비율로 일반 desktop 너비를 여섯 열에 자동 분배하며, 열별 최소 너비와 표의 최소 너비로 실제로 좁은 화면에서는 가로 overflow를 유지합니다. Human의 열 크기 변경과 순서 변경, library가 제공하는 keyboard·focus 동작도 유지합니다. 문서 이름은 DOM API로 안전하게 만들며 http:과 https: 이외의 scheme은 링크로 만들지 않습니다. 외부 링크에는 opener와 referrer 격리를 적용하고 stable source identity를 cell에 보존합니다.

이 표는 source-faithful Original body를 복사·정규화·수정하지 않는 read-only metadata/link projection입니다. Gather 동기화를 소유하거나 실행하지 않습니다. live source/query/API adapter, 동기화 trigger·status, metadata 편집 권한·영속성은 아직 결정되지 않았습니다. sample record나 fake sync action을 만들지 않고 데이터 연결 대기를 표시합니다. 향후 owner-backed loader를 위한 작은 in-browser row adapter만 제공하며, JavaScript나 local dependency가 없을 때도 정확한 여섯 heading과 연결 대기 상태를 읽을 수 있고 초기화 실패는 화면에 드러납니다.

04

프로젝트별 로컬 포트

Workspace는 8000을 사용하지 않으며, 성공적으로 bind한 loopback 포트를 프로젝트별로 기억합니다.

포트를 지정하지 않은 첫 실행은 운영체제가 실제로 배정한 가용 포트 중 8000이 아닌 포트를 서버가 먼저 소유한 뒤 .agent-factory/workspace/port.json에 {"version":1,"port":<port>} 형태로 원자적으로 게시합니다. 다음 실행은 저장된 포트를 bind할 수 있으면 재사용하고, 다른 프로세스가 점유했다면 새 가용 포트를 먼저 bind한 뒤 저장값을 바꿉니다.

--port와 -p는 1부터 65535까지의 명시적 포트를 받지만 8000은 거부합니다. 명시적 포트도 bind 성공 뒤 프로젝트 할당으로 저장됩니다. 잘못된 JSON, 범위 밖 값, symlink, 일반 파일이 아닌 상태, 프로젝트 밖으로 벗어나는 경로는 닫힌 상태로 실패합니다. 이 파일은 Git에서 제외되는 현재 로컬 adapter의 생성 상태이며 packaged browser asset이나 보편 backend가 아닙니다. launcher는 계속 loopback과 기존 allowlist만 제공하고 /common/을 브라우저로 여는 동작을 유지합니다.

05

읽기 모델과 권위

Workspace는 상태를 보여 주고 owner-backed control을 연결하지만 Agent나 Document의 canonical owner가 아닙니다.

Agent-owned db.sqliteowner-provided read-only resultsWorkspace

카탈로그의 schema와 manager, 초기화, rebuild, status, 검색 실행, publication과 recovery는 모두 Agent가 소유합니다. Workspace의 serve.py init은 카탈로그를 만들지 않으며 Workspace는 DB에 직접 접근하거나 명령을 실행하지 않습니다. 향후 명시적인 Agent-owned interface가 제공하는 read-only 결과를 표시할 수 있을 뿐이며, 현재 catalog/search UI나 source/query binding은 구현되지 않았습니다. 원본문서 검색 표에도 Agent 카탈로그 CLI가 연결되어 있지 않습니다.
