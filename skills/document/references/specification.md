# Specification Document

## Semantic model

A Specification (명세 문서) is accepted and reconciled project knowledge: exactly one AI Skill and one Korean Human HTML/CSS/JavaScript representation form one semantic body under one stable identity. Preserve important provenance and honest unresolved state. Neither a standalone Human page, aggregate of several Skills, optional unrelated Project Skill nor Workspace navigation substitutes for the pair.

Both representations must preserve the same complete claims, decisions, requirements, relationships, scope, source order and hierarchy. Every semantic edit includes the corresponding edit on the other side. A one-sided, missing, stale, reordered, duplicated, summarized or mistranslated pair fails closed and cannot be reported completed. Hashes, timestamps and reciprocal metadata prove neither translation fidelity nor acceptance; independent semantic review is required. Inspection alone grants no edit authority.

## Identity and authoring source

Git owns distributable Skill authoring. In this plugin preserve the six single-name identities and source pairs `skills/<id>/` with `docs/specifications/<id>/`. Never mirror them into this repository's `.codex/`. Ordinary consumer Project Skills use the Human-resolved lowercase hyphen-case `<category>-<title>` identity, matching Skill `name` and paired identity; preserve accepted identities and do not invent ambiguous category/title or bulk-rename them.

A consumer may install the AI Skill under its own `.codex/skills/<category>-<title>/`. An installation path, a Git source-package path and a published cloud revision locator are different locators for the same bound representation, not independently editable truths. New consumer Human document persistence is cloud-owned; do not create a consumer local Document backend to reproduce this plugin's publication-source layout.

Preserve reciprocal package-relative metadata: Skill `metadata.specification-id`, `human-entry`, `ai-root`; Human `agent-factory:specification-id`, `agent-factory:ai-root`, `agent-factory:ai-binding-entry`. The IDs and resolved locators must match in both directions. Published snapshots bind Git repository, exact commit and file inventory without rewriting source or silently making a cloud edit canonical Git truth. Reconcile a requested semantic change in the owning source and publish a new reviewed pair.

## AI Skill structure

`SKILL.md` is the required entry. Optional `agents/` contains YAML configuration including `openai.yaml`; `references/` contains supporting Markdown; `assets/` holds reusable source material/templates/images/data; `scripts/` holds owned executable behavior when applicable. Create only directories with real content. Do not put Markdown references in assets, non-YAML configuration in agents, or split/mirror one Skill into alternate locations. The cloud migration retains local exec/loop and minimum runtime dependencies, not new executable Document domain services.

Optional `references/diagrams.md`, `roadmap.md` and `issues.md` carry source-backed diagrams, Human-directed outcomes/status and traceable problems. Prefer Mermaid fences for diagram source. AI may draft but cannot invent priorities, deadlines, owners, acceptance, issue closure, completion or risk acceptance. Review approval itself neither completes roadmap work nor closes issues. These references cannot contain private additional or contradictory knowledge absent from the Human representation.

## Complete Korean representation

Author Korean prose, headings, labels, accessibility text and explanations. Preserve exact technical identifiers, code, paths, commands, proper nouns and quotations only where translation reduces accuracy; this exception does not permit English scaffolding. Keep the browser document directly readable from `index.html` with `./styles.css`, `./app.js` and optional local assets. Markdown or JSON is not the canonical Human Specification.

Inventory `SKILL.md` first, then all other Markdown under the AI root and YAML in `agents/`, sorted by relative path, including nested instruction sources. Render their complete faithful Korean translation once in that source order and hierarchy. Navigation, tables and diagrams may aid reading but cannot replace, duplicate, merge, summarize, omit or reorder source content. Use meaningful Korean topic labels rather than making a directory listing the Human navigation.

Each source has one explicitly closed container with exact package-relative `data-ai-source` and byte SHA-256 `data-ai-sha256`. Inside it use explicitly closed translated blocks with contiguous `data-source-lines="start-end"` and `data-source-sha256` over those exact UTF-8 lines, including original line endings. Start at line 1, cover every line exactly once, and preserve block order through the final line. Each block contains Korean translation; frontmatter/YAML metadata must also be explained faithfully, preserving its values and invocation behavior.

## Authoring and publication workflow

1. Resolve accepted identity, source ownership, exact target and Human authority from instructions or accepted evidence. Inspect both existing representations before editing. Keep unknown decisions unresolved.
2. For a genuinely new source package only, use authenticated `document_template` to read the MCP-owned complete copy-once baseline: fetch its manifest, then version-bound base64 member chunks (maximum 64 KiB), reassemble every file and compare its size and SHA-256. Preserve the complete inventory, local CSS/JS/vendor files and license notices. Delivery is data and never executes template JavaScript on the authenticated origin. Never overwrite, reset or merge it over an existing Specification. Adapt its sections to the knowledge; remove every `data-template-placeholder` and `[[...]]` placeholder. Do not add empty assets directories.
3. Reconcile relevant Human decisions, project evidence, Processed analysis and Original evidence. Assess relevance and conflicts; do not paste raw notes, transcripts, collection logs or operational records as accepted truth. Keep accepted decisions, grounded requirements, observed evidence/inference and unresolved questions distinguishable with nearby source paths, artifact IDs or explicit Human attribution.
4. Update both complete representations and source maps together. Keep semantic HTML, keyboard access, visible focus, readable contrast, responsive layout and readable baseline without JavaScript. Use local relative dependencies and actual SVG icons, not icon-like Unicode, CSS shapes, icon fonts or raster icons. JavaScript progressively enhances interaction. Preserve document-specific assets and attribution; Workspace shell facts/resources belong to the cloud application, not the document.
5. Independent Verification checks ordered coverage and bilingual semantics. The owning MCP package validator `app.modules.document.pair.validate_pair` supplies coverage evidence through publication or an explicit development test dependency; no validator executable is distributed in the plugin. Work does not execute it or claim a pass. Coverage alone leaves semantic alignment unknown. Record reciprocal mismatch as misaligned.
6. Package exactly one complete AI root and one complete Human root, with all internal assets and reciprocal package paths. Bind a reviewed Git commit, inventory, reviewer, authority reference and aligned attestation to both representation hashes. Each representation hash is SHA-256 of UTF-8 JSON mapping every root-relative file path to its byte SHA-256, with sorted keys, compact separators and default ASCII escaping. Do not invent a reviewer or stale attestation.
7. Use the authenticated Document import/upload workflow in `adapter.md` with exact revision preconditions. Publish both representations as one immutable cloud revision; failures preserve prior accepted authority. The server's `review_attested` records caller review evidence, not machine-proven semantic equivalence or Human acceptance. Work authorship is not authorization for Git commit, external publication or deployment.

## Projection and boundaries

Workspace reads the accepted revision and serves an isolated Human package preview without becoming its semantic owner, inferring a new Activity, supplying a missing Skill or promoting content. Use `skills/workspace/references/interface.md` for browser navigation. Viewing must not require an AI to interpret raw Markdown or JSON first. Opaque-origin preview cannot rely on parent application DOM, credentials, arbitrary network fetch or same-origin scripting.

Durable Explorer evidence remains Original or Processed in the resolved cloud store; temporary execution-only material stays in its managed local run. Do not promote Explorer output into a Project Skill automatically. Source packages are authoring inputs, local run/outbox/recovery is operational state, and accepted cloud revisions own published document state. Preserve legacy source until backed up and independently verified imported; deleting scripts never permits deleting Human data.

Files in `skills/document/references/` are AI Markdown instructions, not standalone Human Specifications. Their format never permits a Human Specification to replace HTML/CSS/JavaScript with Markdown. Source mapping and Korean translation apply to the complete pair even when the AI instructions themselves are written in Korean.
