Agent Factory Convention

진입 계약

Agent Factory 코어 개념과 프로젝트 구조·개발·테스트·라이브러리·디자인·주석·문서 유형·권위·Skill 소유권의 공통 규칙에 적용한다. 작업 전에 해당 참조를 모두 읽는다.

공개 배포 Skill은 agent, convention, document, gather, tool, workspace 여섯 개다. Explorer와 Interview는 Agent 역할이 적용하는 Convention 소유 역량이며 추가 공개 Skill·역할이 아니다. Main은 조율하고 Work는 자가 검증·커밋 없이 제한 작업을 수행하며 Verification은 수정 없이 독립 확인한다. 독립 통과 또는 Work 완료 뒤 적용된 근거 있는 Human skip만 END에 도달한다. Main만 정확한 검증·생략 결과 경로의 승인된 일반 Git 커밋을 통합하며 push·amend·역사 변경·무관한 변경 권한은 생기지 않는다.

저장소와 독립적인 문서 유형은 Original, Processed, Specification 세 개다. 개념 순서는 가능한 파생·증거만 나타내며 파이프라인·성숙도·필수 전환·완전성·자동 승격이 아니다. 관계는 없거나 어떤 대응 수든 가능하며 실제 이력을 보존한다. 원본은 기본·출처 적합 형식의 충실도·식별자를 보존한다. 가공은 비권위적 변환 작업 지식이며 수락된 이동 가능한 HTML·CSS·JavaScript 패키지를 쓴다. 기존 Inquery 패키지는 비활성 가공 증거이며 다른 유형·활성 형식 선례가 아니다.

모든 명세는 안정적 식별자 하나 아래 AI Skill 하나와 한국어 Human HTML·CSS·JavaScript 본문 하나를 갖는다. 정확한 출처·연속 줄 해시로 전체 의미·순서·계층·이력을 보존한다. 부분·한쪽만·오래됨·중복·재정렬·요약·오역 쌍은 완료할 수 없다. 독립 의미 검토와 해시 범위는 별개다. Document가 완전한 쌍 게시·이관 계약을 소유한다.

클라우드와 로컬 소유권

Human이 선택한 클라우드 MCP 애플리케이션이 새 문서 저장·검색·게시, 연결·인증·수집 설정, 공유 보고와 Workspace 구현을 소유한다. 새 도메인 작업은 인증된 도구가 제공하는 스키마·안내를 읽고 해당 도구를 쓴다. 역량·연결·테넌트·범위가 없으면 정직하게 실패를 보고한다. 기존 로컬 스크립트 우회, 계정 ID 발명, 로컬 MCP·공급자 서비스 생성을 하지 않는다.

로컬 exec.py, loop.py, 역할 프롬프트와 최소 런타임 의존성은 로컬 세션·프로세스와 실행 사실·그래프 전환·영수증의 권위를 유지한다. 로컬 실행·발신함·복구 상태는 로컬에 남는다. 제한된 Git·도구 조사에는 기존 셸·파일 도구를 쓰고 필요한 증거를 승인된 클라우드 Document 도구로 업로드한다. 공유 보고는 로컬 실행을 시작·완료하지 않는다. 계획 작업 상태는 백그라운드 작업·런타임 관찰과 별개다.

Git은 배포 Skill 작성 소스를 소유한다. 플러그인의 skills/<id>/와 docs/specifications/<id>/는 상호 게시 소스 패키지이며 소비자 로컬 런타임 저장소나 독립 편집 클라우드 진실이 아니다. 여섯 이름·메타데이터 식별자를 유지하고 저장소 .codex/에 복제하지 않는다. 소비자 Project Skill은 Human이 확인한 <category>-<title> 이름을 보존한다. 소스 패키지·설치 Skill·클라우드 리비전 위치를 구분한다. 게시된 완전한 쌍은 Git 저장소·정확한 커밋·목록·검토된 표현 해시에 결속되며 클라우드가 수락된 불변 리비전을 소유한다.

새 카탈로그·검색과 문서·동기화 설정은 클라우드 소유다. 남아 있는 .agent-factory/db.sqlite, 기존 로컬 문서·동기화 설정은 가져오기가 독립 검증될 때까지 이관 입력이다. 로컬 도메인 실행 파일은 퇴역했고 재사용 Document 저작 자원은 MCP 패키지 소유다. 목록화·독립 백업·가져오기 검증 전까지 데이터를 보존하며 코드 폐기는 삭제 권한이 아니다. 계약 변경에서 등록·설정 계정·배포·전체 이관 완료를 주장하지 않는다.

Workspace는 일정, 에이전트, 문서, 외부연동, 로그, 테스트 순서의 정확히 여섯 Activity를 가진 Human 관제탑이다. 상세 수락 구조·계획·Human 소유 미결정은 Workspace 참조가 소유한다. MCP 애플리케이션이 셸·자산을 소유하므로 소비자 프로젝트에 브라우저 런타임을 복사하지 않는다. Tool은 논리 생명주기 경로를 소유하고 실제 호스트·공급자·클라우드 자격증명 권위는 상태를 유지한다. Tool 준비 상태는 실행 권한·자동 범위 확대를 주지 않는다.

권위와 식별자

공개 배포 Skill은 agent, convention, document, gather, tool, workspace 여섯 개이며 코어 역량은 이 여섯 개와 Explorer·Interview를 합한 여덟 개다. Explorer·Interview는 Agent 역할이 적용하는 Convention 소유 역량으로 공개 Skill·추가 Agent 노드가 아니다.

명세 하나는 안정적 식별자 하나 아래 확인된 AI Skill 하나와 한국어 Human 브라우저 문서 하나를 갖는 수락 의미 본문이다. 구체 위치는 어댑터가 확인하며 외부 백엔드는 일대일 쌍을 유지하면서 다른 위치를 쓸 수 있다. 두 표현은 동일한 출처 순서·계층·의미·식별자·이력을 보존한다. 상호 메타데이터만으로 정렬을 증명하지 못한다. 한쪽 변경은 미완료·허용 불가이며 완료로 보고하지 않는다. 부분·오래됨·재정렬·중복·요약·오역도 실패 처리한다.

이 저장소의 convention 쌍은 다음과 같다.

skills/convention/
docs/specifications/convention/

저장소 로컬 .codex/skills/ 복제본을 만들지 않는다. 탐색·표·도식은 전체 Human 번역을 보완할 수 있지만 대체·반복하지 못한다.

Project Skill 이름

일반 소비자 프로젝트 쌍은 Skill 이름과 쌍 표현에 Human이 확인한 소문자 하이픈 <category>-<title> 식별자 하나를 사용한다. 설치 Skill은 <project-root>/.codex/skills/<category>-<title>/에 둘 수 있다. 기존 .agent-factory/document/specification/<category>-<title>/ Human 소스 패키지는 이관 입력이며 새 소비자 런타임 루트가 아니다. 게시 Human 리비전 위치는 클라우드가 확인한다.

분류·제목을 추론하거나 수락 식별자를 일괄 변경하지 않는다. 플러그인은 명시적인 단일 이름 예외다. 소스·설치·게시 위치에서 일대일 쌍을 보존한다.

문서와 저장

Document는 정확히 세 저장 독립 유형을 포괄한다.

  • 원본 문서(Original): 기본·출처 적합 형식의 출처 충실 증거.
  • 가공 문서(Processed): 변환된 비권위적 작업 지식.
  • 명세 문서(Specification): 위 동기화 Human·AI 쌍을 가진 수락·조정 프로젝트 지식.

Original -> Processed -> Specification은 가능한 증거·파생 관계만 표현한다. 파이프라인·상태 기계·성숙도·필수 전환·완전성·일대일 대응이 아니다. 관계는 임의 대응 수를 갖거나 없을 수 있고 실제 관계에만 이력을 기록한다. Refined는 네 번째 유형이 아니다.

활성 가공·Human 명세는 이동 가능한 index.html, styles.css, app.js 패키지를 공유하지만 권위·AI 쌍을 공유하지 않는다. 역사적 legacy-inquery-*는 비활성 가공 증거로 남는다.

Human이 선택한 클라우드 MCP 애플리케이션이 새 문서 저장·검색·게시, 연결·인증·수집 설정, 공유 보고·Workspace를 소유한다. Git이 배포 Skill 작성을 소유한다. 로컬 버전 관리 한국어 HTML은 쌍 게시 소스이며 소비자 백엔드·독립 편집 클라우드 진실이 아니다. 게시 완전 쌍은 Git 저장소·정확한 커밋·내용 목록·검토된 표현 해시에 결속된다. 상호 메타데이터·안정 식별자를 유지하며 소스 패키지·설치 Skill·클라우드 리비전 위치를 구분한다.

로컬 exec·loop·프롬프트·최소 런타임 의존성은 프로세스·세션·실행·그래프 권위를 유지한다. 실행·발신함·복구는 로컬에 남고 기존 셸·파일 도구로 조사하며 승인된 클라우드 도구로 필요한 영속 증거를 전달한다. 제공된 인증 스키마·안내를 먼저 읽는다. 역량·연결·테넌트·범위가 없으면 정직하게 실패를 보고하며 로컬 MCP·공급자 서비스를 만들거나 계정을 추론하지 않는다. 기존 데이터·설정·카탈로그는 목록화·독립 백업·가져오기 검증까지 보존한다. 로컬 도메인 실행 파일은 검증된 대체 구현 이후 퇴역했다. 코드 폐기는 Human 데이터 삭제를 허용하지 않는다. 클라우드 선택은 수락됐지만 실제 테넌트·계정·자격증명 식별자와 미해결 파괴·충돌 결정은 Human 소유다.

어댑터 경계

문서 어댑터 초기화·물리 이관은 공개 document Skill 소유이며 의미 분류·변환·조정·수락과 별개다. 물리 이관은 documentType·식별자·이력·권위·명세 쌍을 보존한다.

LLM 출력은 자문·작성용이며 실행 내용이 아니다. 결정적 관리자는 현재 상태·필요 Human 권위를 재확인한 뒤 폐쇄된 버전별 허용 계획·IR만 실행할 수 있다. 오래된 계획·경로 탈출·심볼릭 링크·미해결 충돌·미지원 작업·유형 승격·미승인 파괴·무결성 불일치는 실패한다. 명세 쌍은 복구 가능한 그룹 하나로 게시한다.

역량 소유권

  • Gather는 제한 외부 출처를 선택·동기화해 원본으로 만들며 충실도·식별자·이력·목적지·읽기 의도를 보존한다.
  • Tool은 논리 발견·생명주기·연결·범위·상태·역량 메타데이터를 관리한다. 각 호스트·플러그인·MCP 서버·프로젝트 매니페스트·공급자는 권위를 유지한다. 비밀을 저장하거나 Agent·Gather 작업을 실행하지 않는다.
  • Explorer는 Work의 제한 증거 탐색을 수행하고 원본·가공 증거를 만들 수 있다. Human 인터뷰·명세 수락은 하지 않는다.
  • Interview는 Human 대화에서 Main이 수행하는 적응형 질문이다. 기본으로 가공 지식을 만들고 권위·수락을 부여하지 못한다.
  • Document는 세 문서 유형과 확인 대상의 의미 작업을 소유한다.
  • Convention은 코어 모델·공통 규칙을 소유한다.
  • Agent는 Main -> Work -> Verification 그래프·역량 결속·로컬 사실·전환·영수증을 소유한다.
  • Workspace는 Human 관제탑이며 소유자 근거 상태만 투영한다.

연결 기반 수집에서 Gather는 역량·정확한 출처 한도·확인 목적지·최소 요청 범위·Human 또는 관리자 승인을 선언한다. Tool은 확대 없이 연결 상태·실제 허용 범위를 보고한다. 새 공급자 작업은 클라우드 Tool 연결·인증 도구와 Gather 수집 도구가 소유하고 공급자 실행 파일은 퇴역했고 기존 토큰 캐시는 해당 자격증명 권위에 남는다. Tool은 범위를 자동 확대하거나 .agent-factory/tool/을 만들지 않는다. Workspace는 외부연동 투영을 소유하고 실제 공급자·클라우드 자격증명 권위는 상태를 유지한다.

Agent 그래프와 엔지니어링 계층

Main은 Human 인터뷰·권위 확인·분해·제한 위임·검증 결과 통합·승인된 제한 Git 게시를 소유한다. Work는 실행하지만 검증·커밋하지 않는다. Verification은 최신 Work를 독립 확인하고 수정하지 않으며 실패를 같은 Work 세션으로 돌린다. Verification 통과 또는 현재 Work 완료 뒤 근거 있는 Human skip이 적용될 때만 그래프가 끝난다.

Main은 해당 결과 경로만 스테이징하고 커밋 요청에서 push·amend·force·역사 변경·reset·restore·삭제를 추론하지 않는다. Human 소유 우선순위·마감·담당자·수락·위험 수용·완료는 명시 결정까지 미해결이다.

Human skip 의도는 다음 Verification 시작 전에 Human 행위자·권한 참조·결정 증거를 기록한다. 기록은 전환·완료가 아니다. 현재 최초·수정 Work 완료 뒤 적용되어 다음·추가 Verification 없이 END로 간다. 비Human skip은 실패한다.

Agent 엔지니어링은 다섯 중첩 범위로 확장된다.

  1. Prompt Engineering: 모델 상호작용 하나를 형성한다.
  2. Context Engineering: 제한 증거·도구 맥락을 조립한다.
  3. Loop Engineering: 반복·피드백·중단·복구를 통제한다.
  4. Agent Graph Engineering: Human·Agent·작업·도구·상태·증거를 조율한다.
  5. Agentic Engineering: 전체 생명주기·안전·평가·관찰 가능성·거버넌스를 통제한다.

카탈로그와 Workspace

새 카탈로그·검색·공유 보고는 클라우드 소유다. 로컬 db.sqlite는 보존된 기존 비권위 데이터이며 새 작업 경로가 아니다. 보고 작업 상태·프로세스 관찰·계획 작업은 로컬 실행·루프를 실행하거나 완료하지 않는다. 소유 스키마를 읽고 신선도·의미 결과·그래프 END를 구분한다.

Workspace는 작업 표시줄 -> 기본 사이드바 -> 작업 영역과 일정, 에이전트, 문서, 외부연동, 로그, 테스트 순서의 정확히 여섯 Activity를 쓴다. 외부연동 사이드바 목적 그룹 순서는 웹·리서치, 문서·파일, 메일·메시지, 일정·회의, 지식·업무관리, 개발·운영, 데이터·비즈니스다. 문서 사이드바는 원본 문서·가공 문서·명세 문서를 쓰며 논리 유형·식별자·메타데이터·경로를 바꾸지 않는다. 상세 정보 구조는 skills/workspace/references/activities.md, 브라우저·탭·분할·실행기·게시·보안은 skills/workspace/references/interface.md 소유다. 미해결 실시간 연동·원본 출처와 질의 동작·변경 권위·Activity 세부를 발명하지 않는다.

MCP 애플리케이션은 Workspace FastAPI 런타임·MCP 전송·발견 경로·배포 어댑터·테스트·static/workspace/의 정식 브라우저 자산을 소유한다. 플러그인은 Workspace Skill·Human 명세 계약을 유지한다. 소비자는 문서 백엔드·셸 복사본·루트 실행기 없이 자체 Skill 설치·로컬 실행 데이터를 유지한다.

개발 규칙

변경 경계

  • 각 변경은 요청 동작에 한정된 독립 단위로 유지한다. 무관한 Human 작업·공개 계약·저장 권위·수락 식별자를 보존한다.
  • 함께 처리하면 검토·복구를 어렵게 하는 넓은 형식 정리·이름 변경·리팩터링은 동작 변경과 분리한다.

구현 선택

  • 수락 요구를 만족하고 기존 코드에 맞는 가장 작고 유지 가능한 구현을 우선한다.
  • 병렬 추상화를 추가하기 전에 기존 추상화를 재사용한다. 현재 스택·표준 라이브러리로 충분하면 의존성을 추가하지 않고 선택 시 libraries.md를 읽는다.
  • 파일 대상·어댑터 선택을 명시한다. 저장 백엔드를 조용히 선택·복제·이관·확대하지 않는다.
  • 초기화·틀 생성은 기본적으로 기존 파일을 보존한다. 덮어쓰기·병합·강제 동작은 정확한 대상에 명시적으로 정의한다.
  • 생성·복사 자산과 재사용 소스를 구분하고 둘을 유지할 때 동기화 계약을 기록한다.

유지보수성

  • 이름·인터페이스를 소유 도메인과 일치시킨다.
  • 재사용 실행 동작은 스크립트에, 상당한 조건별 지침은 집중 참조에 두며 진입점마다 복제하지 않는다.
  • 코드 변경에 영향받는 문서·주석을 갱신한다. 주석·문서 주석·TODO는 annotation.md를 읽는다.
  • 관찰 동작을 수락 결정·추론 상태·미해결 질문과 구분해 보고한다.

Git 커밋 게시

  • 승인된 Git 커밋은 Work·Verification이 아닌 Main 소유의 제한 결과 통합·게시다. Work와 Verification은 커밋하지 않는다.
  • 독립 Verification 통과 또는 현재 Work 완료 후 근거 있는 Human skip 적용 뒤에만 Main이 신속히 직접 커밋한다. 별도 커밋 Work 턴을 위임하거나 Main -> Work -> Verification에 커밋 노드·역할을 추가하지 않는다.
  • 스테이징 전 Main은 최신 Work 결과·영수증, Verification 통과 영수증 또는 Human skip 근거, 현재 Git 상태·차이를 조사한다. 해당 결과의 정확한 경로만 스테이징한다. 무관한 dirty·untracked·generated·runtime 변경을 제외하고 명세의 완전한 동기화 Human·AI 쌍을 보존한다.
  • 커밋 요청은 정확한 범위의 일반 커밋만 허용한다. push·amend·force·역사 변경·reset·restore·삭제·무관한 변경 포함 권한을 추론하지 않는다. 안전한 정확 스테이징·일반 커밋이 불가능하면 범위를 넓히지 않고 장애를 보고한다.

행동 도식

게임 몬스터·NPC·보스의 결정 패턴을 문서화한다. 의도·관찰 행동을 시각화하며 실행 게임 AI가 아니다.

형태 선택

  • 유한 상태 기계는 Mermaid stateDiagram-v2로 상태·이벤트·가드·전환·초기·종료·보스 단계를 나타낸다.
  • Behavior Tree는 Mermaid flowchart로 Root·Selector·Sequence·Condition·Action과 이해에 필요한 Success·Failure·Running 결과를 나타낸다.
  • 플레이어·NPC·보스·환경·게임 시스템 사이 상호작용 시간 순서가 주 질문이면 sequenceDiagram을 쓴다.

제어 노드·평가 의미를 명시하지 않은 일반 순서도를 Behavior Tree라고 하지 않는다. 경계를 이름 붙이지 않고 FSM·Behavior Tree 표기를 합치지 않는다.

내용 규칙

  • 게임 설계·코드의 도메인 용어로 상태·행동을 이름 붙인다.
  • 전환을 일으키는 이벤트·가드를 표시하며 임계값·확률·재사용 대기·우선순위·단계 조건을 발명하지 않는다.
  • 조건·행동, 인터럽트·일반 전환을 구분한다.
  • 이해에 영향 주는 반복·종료 행동은 명시한다.
  • 구현 관찰을 희망 설계·미해결 행동과 구분한다.
  • 행동·핵심 분기를 설명하는 accTitle·accDescr을 넣는다.

런타임 경계

Mermaid.js는 문서만 렌더한다. Behavior Tree 엔진·FSM 런타임·계획기·결정 엔진·시뮬레이터·디버거·원격 측정 뷰어·실행 진실의 출처가 아니다. 별도 조사 증거 없이 그래프가 게임에서 실행되거나 현재 빌드와 같거나 런타임 논리와 동기화됐다고 주장하지 않는다.

향후 시각 노드 편집·실시간 시뮬레이션·추적·코드 생성이 필요하면 별도 도구·아키텍처 결정으로 해결한다. 이 문서 규칙을 엔진 계약으로 확대하지 않는다.

  • 수락 도메인·스키마 증거의 단수형 안정 엔터티 이름을 쓴다.
  • 식별자·조인을 이해하는 데 실질적으로 도움 될 때 기본키·외래키를 표시한다.
  • 관계를 이름 붙이고 대응 수·선택성을 명시한다.
  • 개념·논리·물리 ERD를 구분하며 추론 개념 모델을 구현 DB 스키마로 제시하지 않는다.
  • 완전 물리 스키마를 명시 요구하지 않으면 목적에 필요한 속성만 포함한다.
  • 이름만으로 테이블·키·제약·관계를 발명하지 않는다.
  • 엔터티·주요 대응 수를 설명하는 accTitle·accDescr을 넣는다.

렌더링 도식보다 이관·스키마 파일·수락 명세의 권위를 유지한다. 코드·DB에서 도출하면 출처 이력을 기록한다.

배포 소스와 설치

플러그인의 여섯 배포 Skill은 <plugin-root>/skills/<id>/ 아래 두며 저장소 .codex/에 복제하지 않는다. 각각 <plugin-root>/docs/specifications/<id>/의 버전 관리 한국어 게시 소스와 짝을 이룬다. 상호 메타데이터는 패키지 상대 위치이며 여섯 단일 이름 식별자를 보존한다. 이는 소스 패키지이며 소비자 문서 백엔드 루트가 아니다.

일반 소비자의 자체 Project Skill은 .codex/skills/ 아래 수락된 소문자 하이픈 <category>-<title> 식별자를 쓴다. 소스 패키지·설치 Skill·클라우드 불변 리비전 위치는 따로 확인해 표현 하나를 결속하며 여러 편집 진실을 만들지 않는다. Git이 배포 작성을 소유하고 클라우드 게시는 저장소·정확한 커밋·전체 목록·검토된 완전 Human·AI 쌍에 결속된다. 개발 형제 경로 ../mcp를 설치 경로로 고정하지 않는다.

Agent가 운영 세션·실행 상태·요청·결과·영수증·하트비트와 이벤트·로컬 보고 발신함과 확인·복구를 소유한다. 기존 exec·loop 진입점·필수 지원 모듈·확장 경로와 배치 호환성을 유지한다. 실행 전용 임시 Explorer 자료는 생성 실행에 남으며 독립 루트가 없다. 자격증명은 소유 권위에 남고 런타임 증거나 버전 관리에 들어가지 않는다.

클라우드 소유 도메인

선택된 인증 Agent Factory MCP 애플리케이션이 새 문서 저장·메타데이터·불변 본문 리비전·색인과 검색·연결과 인증·수집 설정·공유 보고·Workspace를 소유한다. PostgreSQL은 테넌트 메타데이터, 객체 저장소는 불변 문서 바이트를 소유한다. 런타임 소스·의존성 매니페스트·브라우저 자산·배포·테스트는 그 애플리케이션 소유다. Workspace는 프로젝트 .agent-factory/workspace/, 실행기·포트 파일·브라우저 셸 복사본을 만들지 않는다. 비권위적 클라이언트 설치·연결 캐시는 저장소 밖 ~/.agent-factory/에 둘 수 있다.

새 로컬 db.sqlite, 문서·동기화 설정이나 .agent-factory/tool/ 저장소를 만들지 않는다. 실제 호스트·플러그인·MCP 서버·패키지 매니페스트·자격증명 권위가 각 상태를 유지한다. 제공된 인증 스키마·안내를 읽고 선택 역량·계정·권한이 없으면 정직하게 실패를 보고한다.

기존 출처와 이관

기존 로컬 .agent-factory/document/{original,processed,specification}/, document/sync.json, 출처 모음, SQLite와 보조 파일은 목록화·독립 백업·가져오기 검증까지 이관 입력으로 보존한다. 기존 직접 패키지는 바로 아래 디렉터리 하나가 문서 하나이며 내부 파일·하위 디렉터리는 그 문서에 속하고 생산자·분류 래퍼는 식별자가 아니다. processed/legacy-inquery-<legacy-id>/는 legacy 상태·이력을 가진 비활성 가공 증거이며 다른 유형·활성 작업 공간이 아니다.

원본은 다양한 기본·출처 적합 바이트를 보존한다. 활성 가공은 이동 가능한 index.html, styles.css, app.js 패키지를 쓰며 Human 명세와 형식이 같아도 AI Skill 쌍·명세 권위는 생기지 않는다. 물리 이관은 유형·식별자·이력·쌍을 보존하고 루트는 흐름·승격을 뜻하지 않는다. 코드·스크립트 폐기는 Human 데이터·출처·자격증명·백업 삭제를 허용하지 않는다. 전환·파괴 작업·미해결 충돌 정책은 정확한 Human 권위를 유지한다.

생태계 경계

이 소유 배치는 보편 애플리케이션 소스 트리가 아니다. 소유 생태계가 수락한 배치·의존성 안내를 따른다. 예를 들어 Python 패키징은 가져오기·설치 절충이 다른 src·flat 배치를 제공한다. 근거: https://packaging.python.org/en/latest/discussions/src-layout-vs-flat-layout/ . Agent Factory 런타임 경로를 무관한 애플리케이션 코드에 강요하지 않는다.

명시적 Human 입력 규칙

명시성 경계

요구·선택·범위·권한 부여·인수 기준은 Human이 실제로 말했거나 이미 수락한 명세가 모호함 없이 결정한 경우만 명시적으로 취급한다.

필수 부분이 명시되지 않았으면 추론·발명·묵시적 기본값·가정을 결정처럼 제시하지 않는다. Human에게 묻고 답을 기다린 뒤 해당 결정을 통과한다. 침묵·모호함·관행·선례·그럴듯한 선호·이의 없음은 명시적 결정이 아니다.

증거와 역할

저장소 조사·증거 수집은 관찰 사실을 밝힐 수 있지만 빠진 Human 결정을 만들어내지 못한다. 발견한 사실과 Human 소유 선택을 구분한다.

Main·Work·Verification·Explorer·Interview에 적용한다.

  • Main은 필요한 빠진 결정을 Human에게 묻고 답을 기다린다.
  • Work·Verification은 미해결 질문을 Main에게 보고하며 Human에게 직접 묻거나 해당 결정을 통과하지 않는다.
  • Explorer는 관찰 사실의 증거를 수집할 수 있지만 Human 소유 선택으로 바꾸거나 Human을 인터뷰·사칭하지 않는다.
  • Interview는 Main만 수행하며 직접 Human 발언·증거·해석·미해결 공백을 구분한다.

새 Agent 역할·공개 Skill·역량을 만들지 않으며 기존 안전·권위·명세 쌍·관리 그래프 계약을 약화하지 않는다.

  • 관찰·분석·가설·결론·모순·제약을 구분한다.
  • 위임 질문·범위·제약·완료 조건·증거 경계를 보존한다.
  • Human 소유 제품 방향·우선순위·승인·수락·완료·위험 허용을 선택하지 않는다.

Agent Factory 기본값

  • 필요한 동작을 제공하면 로컬 초기화·서빙·저장소 유틸리티에 Python 표준 라이브러리를 우선한다.
  • 이동 가능한 Human 문서·기본 Workspace 셸은 의미 HTML·CSS·바닐라 JavaScript를 우선한다. 의존성은 로컬 상대 경로에 두고 JavaScript는 점진 강화에 쓴다.
  • 조회·버전 관리 가능한 ERD·게임 행동·시퀀스에는 Mermaid.js를 기본 JavaScript 렌더러로 사용한다. Mermaid 소스가 유지 산출물이며 SVG는 투영이다.
  • 기존 프로젝트 SVG 자산을 먼저 재사용한다. 실제 SVG를 렌더하고 출처·라이선스가 호환될 때만 유지되는 아이콘 라이브러리를 허용한다.

명시적 Human 선택·더 강한 프로젝트 규칙을 덮어쓰지 않는다. 다른 Agent가 일관되게 적용해야 하는 프로젝트별 라이브러리 결정은 소유 명세·Project Skill에 기록한다.

Mermaid.js 경계

Mermaid.js는 문서 렌더러이며 게임 AI 런타임·Behavior Tree 엔진·결정 엔진·시뮬레이터·디버거가 아니다. 포함됐다고 행동 그래프의 실행성이나 게임 런타임과 동기화를 추론하지 않는다.

브라우저 통합 시 다음을 적용한다.

  • CDN 대신 로컬 상대 의존성으로 제공한다.
  • 명시 보안 검토가 다른 설정을 승인하지 않으면 기본 securityLevel: "strict"를 유지한다.
  • 폐기된 mermaid.init 대신 mermaid.run을 쓴다.
  • 작성 도식에 accTitle·accDescr을 넣는다.
  • JavaScript가 없어도 읽을 수 있는 소스·의미 설명을 남긴다.
  • 소유 프로젝트 의존성 매니페스트·벤더 자산 기록에 선택 버전·출처·라이선스·갱신 방법을 선언한다.

이 규칙은 렌더러를 선택할 뿐 Mermaid.js 설치·벤더링·업그레이드를 수행하지 않는다.

근거

기존 의존성·표준 라이브러리를 먼저 확인하라는 OpenSSF 지침을 따르되 성숙한 기능을 재구현하면 자체 결함이 생길 수 있음을 인정한다. 직접 의존성 채택 전 평가하고 올바른 출처에서 가져와 프로젝트 패키지 관리자로 관리하며 갱신 가능하게 유지한다.

  • OpenSSF 보안 개발 간결 안내: https://best.openssf.org/Concise-Guide-for-Developing-More-Secure-Software.html

SVG 아이콘만 사용

규칙

모든 사용자 아이콘에 SVG를 쓴다.

다음으로 아이콘을 구현하지 않는다.

  • Emoji.
  • 갈매기표·불릿·삼각형·글리프 같은 Unicode 기호.
  • 아이콘 폰트.
  • 아이콘처럼 사용하는 텍스트 레이블.
  • CSS만으로 만든 기하 도형.
  • PNG·JPG·GIF·WebP 등 래스터 이미지.

허용 SVG 형식

다음 중 하나를 쓴다.

  • HTML의 인라인 <svg>.
  • 실제 <svg> 요소를 렌더하는 프레임워크 구성요소.
  • 기존 코드가 지원하면 <img src="...svg">, <use href="..."> 또는 동등한 방식의 .svg 자산 참조.
  • SVG 출력을 만드는 유지 중인 SVG 아이콘 라이브러리.

더 강한 로컬 SVG 자산·심볼 패턴이 없으면 작은 애플리케이션 UI 제어에는 인라인 SVG를 우선한다.

작업 흐름

  1. 편집 전 대상 UI·기존 아이콘 패턴을 조사한다.
  2. 변경 영역의 모든 아이콘 유사 글리프·CSS 도형을 SVG로 바꾼다.
  3. 접근 가능한 이름은 SVG 내부뿐 아니라 상호작용 요소에 둔다.
  4. 장식 SVG는 aria-hidden="true", focusable="false"로 표시한다.
  5. 보이는 텍스트와 아이콘 마크업을 분리한다.
  6. 최종 DOM·소스에서 변경 아이콘이 SVG인지 확인한다.

프런트엔드 확인

UI 검토·구현 시 다음을 특히 살핀다.

  • ›, ⌄, ▸, ▾, ▲, ▼, ←, → 등의 갈매기표 문자.
  • 아이콘으로 쓰는 ... 버튼 레이블.
  • 실제 SVG 출력이 없는 CSS ::before·::after 아이콘.
  • 아이콘 폰트 클래스 이름.
  • 실제 인라인 SVG가 더 명확하고 조사하기 쉬운 위치에 쓰는 Data URI 마스크.

변경 아이콘 영역에 있으면 Human이 아이콘 작업을 명시 제외하지 않은 한 SVG로 바꾼다.

출처와 라이선스

기존 프로젝트 SVG를 먼저 쓴다. 외부 아이콘 세트에서 경로를 가져오면 라이선스가 요구하는 경우 관련 산출물·코드 주석에 출처·라이선스를 기록한다.

테스트 규칙

구현·유지보수·Verification이 테스트를 선택하거나 실행할 때 적용한다.

집중 실행

  • 실행을 최소화하고 소유 구성요소·변경 계약의 가장 작은 관련 집중 테스트 집합을 실행한다.
  • 소유 프로젝트의 기존 실행기·프레임워크·구성요소 경계·테스트 조직에서 범위를 확인한다. 특정 실행기·프레임워크·명령·디렉터리는 보편 규칙이 아니다.
  • 집중 증거가 도메인 간 영향을 보이거나 Human이 넓은 검사를 명시적으로 요청한 경우만 확대한다.
  • Human의 명시 요청 없이는 저장소 전체 또는 다른 전체 테스트를 실행하지 않는다.

Agent 그래프 경계

집중 범위는 Agent Factory 독립 Verification을 합치거나 대체·생략하지 않는다. Verification은 Work 결과를 독립 확인하고 변경 구성요소·계약의 가장 작은 관련 테스트를 선택한다. 확대 규칙도 동일하다. 집중 증거가 도메인 간 영향을 보이거나 Human이 넓은 범위를 명시 요청할 때만 확대하며 전체 실행에는 명시적 Human 요청이 필요하다.
