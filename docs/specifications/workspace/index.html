메타데이터 이름: workspace. 설명: 일정·에이전트·문서·외부연동·로그·테스트의 정확히 여섯 최상위 Activity를 가진 Human 관제탑을 제공한다. 셸·탐색 작업에 사용하며 미결정 세부를 추론하거나 투영 상태를 소유하지 않는다. 명세 ID는 workspace, Human 진입점은 docs/specifications/workspace/index.html, AI 루트는 skills/workspace/다.

Agent Factory Workspace

진입 계약

Human 대면 프로젝트 관제탑에 사용한다. 주요 영역은 작업 표시줄(Activity Bar)·기본 사이드바(Primary Sidebar)·작업 영역(Workspace area)이다. Activity 순서는 일정, 에이전트, 문서, 외부연동, 로그, 테스트 여섯 개이며 추가·별칭을 만들지 않는다.

Workspace는 투영·제어 화면이다. Agent·Document·Gather·Tool·공급자·자격증명·카탈로그 상태를 소유·실행하지 않는다. 소유자 근거가 있는 사실·제어만 표시하고 미결정은 미결정으로 보이게 하며 설정·로컬 산출물에서 실제 상태·샘플 데이터를 발명하지 않는다.

작업 선택

작업 전 해당 참조를 끝까지 읽는다.

  • references/activities.md: 여섯 Activity 정보 구조·외부연동 분류·문서 사이드바·발견 상태·미해결 범위.
  • references/interface.md: 브라우저 셸·접근성과 시각 동작·문서 표와 탐색기·재귀 명세 탭과 분할·MCP 런타임 게시와 서버 동작·저장과 권위 경계.

정보 구조·인터페이스를 함께 바꾸면 둘 다 읽는다. 수락된 개발 일정 모델·화면·저장·제어는 references/planning.md도 읽으며 이전 일정 미결정 문구보다 우선한다. 상세 계약을 여기 반복하지 않는다.

런타임과 저장

플러그인은 Workspace Skill·Human 명세를 소유한다. 선택 Agent Factory MCP 애플리케이션이 구현을 소유·제공한다.

<agent-factory-mcp>/app/                 FastAPI·MCP·도메인 런타임
<agent-factory-mcp>/static/    정식 브라우저 자산
<agent-factory-mcp>/tests/               런타임 계약 테스트

형제 개발 체크아웃에서 <agent-factory-mcp>는 ../mcp이며 보편 설치 요구가 아니다. 플러그인에 런타임을 재생성하거나 대상 프로젝트에 브라우저 자산을 복사하지 않는다.

소비자 프로젝트에는 .agent-factory/workspace/, Workspace 복사 자산·실행기·포트 파일·소유 투영을 두지 않는다. PostgreSQL·객체 저장소가 테넌트 Workspace 데이터의 권위다. 클라이언트는 저장소와 분리된 ~/.agent-factory/에 비권위 설치·연결 상태를 둘 수 있다. 기존 로컬 문서는 출처 트리 폐기 전에 목록화·백업·MCP 가져오기가 필요하며 이관은 출처 삭제 권한이 아니다.

새 도메인 작업은 확인된 인증 클라우드 도구·현재 서버 스키마와 안내를 사용한다. Document 도구는 저장·검색·게시, 연동·수집 도구는 연결·수집, 보고 도구는 공유 실행 보고를 소유한다. 로컬 exec·loop는 그래프 권위를 유지하고 클라우드 계획 작업·백그라운드 작업은 별개다. 도구·계정·범위가 없으면 기존 스크립트·로컬 서비스 우회 없이 실패를 보고한다. Git은 Skill·한국어 HTML 게시 소스를, 클라우드는 저장소·커밋·목록에 결속된 수락 완전 쌍 리비전을 소유한다. 소스 위치는 소비자 런타임 경로가 아니다.

완료 조건

Workspace 변경 완료 조건은 다음과 같다.

  • 여섯 순서 Activity·결정과 미결정 경계가 references/activities.md와 일치한다.
  • 변경 브라우저·탐색·접근성·보안·게시 규칙이 references/interface.md와 일치한다.
  • 변경 런타임 동작에 대해 선택 MCP의 집중 테스트가 통과한다.
  • 투영 도메인 상태를 발명·변경·인수하지 않았다.
  • 이 Skill·Human 명세가 동기화돼 있다.

Workspace 활동

최상위 계약

정확히 여섯 Activity 순서는 다음과 같다.

  1. 일정
  2. 에이전트
  3. 문서
  4. 외부연동
  5. 로그
  6. 테스트

정확한 한국어 레이블을 작업 표시줄의 장식 SVG 아래 표시한다. 별칭·Activity를 추가하지 않는다. 순서는 도메인 소유권·작업 흐름이 아니다.

외부연동은 기본 사이드바·작업 영역을 갖는 일반 Activity이며 하단 유틸리티가 아니다. 기본 사이드바는 비상호작용 목적 그룹 일곱 개를 다음 순서로 갖는다.

  1. 웹·리서치
  2. 문서·파일
  3. 메일·메시지
  4. 일정·회의
  5. 지식·업무관리
  6. 개발·운영
  7. 데이터·비즈니스

공급자·계정·연동 방법·상태·권한 범위·마지막 동기화 시각은 분류 축 아닌 항목 속성이다. 분류는 연결·출처 선택·중첩 탐색·분류 전용 제어를 뜻하지 않는다. 작업 영역은 정직한 외부연동 상태 연결 대기로 시작하고 소유자 근거 사실만 표시한다. 상세 렌더링·향후 로더 계약은 references/interface.md 소유다.

문서 사이드바

독립 접기 그룹 순서는 원본 문서·가공 문서·명세 문서다. 정확한 Human 레이블이며 논리 유형·식별자·메타데이터·경로를 바꾸지 않는다.

원본

원본에는 개요·문서검색이 있다. 검색은 간결한 의미 표를 쓴다. MCP 애플리케이션은 플러그인에 브라우저 라이브러리 배포를 요구하지 않고 전역 검색·열별 필터·정렬·Human 크기와 순서 조정을 제공할 수 있다. 열 순서는 다음과 같다.

  1. 문서 분류
  2. 출처
  3. 태그
  4. 문서 이름
  5. 확장자
  6. 수정 일자

문서 이름 셀만 출처 원본 링크다. 공급자 셀은 보이는 공급자 글·장식 인라인 SVG를 유지한다. 읽기 메타데이터·링크 투영이며 Workspace는 원본을 복사·변경하거나 Gather 동기화를 소유하지 않는다.

가공과 명세

각각 개요 바로 뒤에 보이는 탐색기 부모 행을 둔다. 실제 문서 목록·정직한 상태는 부모 안에 중첩한다. 가공 발견은 승인 테넌트 문서·불변 리비전을 읽으며 로컬 프로젝트를 훑지 않는다. 브라우저 진입점이 없으면 사용 불가를 보이고 가능할 때 인증 패키지 미리보기를 쓴다.

명세 발견은 Human·AI 상호 메타데이터를 비교해 paired·misaligned·missing-human을 보고한다. paired만 탐색 가능하다. 선택하면 읽기 편집 그룹에서 Human 브라우저 문서를 열거나 활성화한다. 탐색기는 실제 트리이며 드래그 대신 클릭도 지원한다.

행 치수·짧은 제목·인증 리비전 전달과 격리 미리보기·키보드·탭·닫기·끌어놓기·재귀 분할·빈 상태·iframe·정리 규칙은 references/interface.md에만 둔다.

개발 일정

일정은 domain -> feature -> implementation issue 계획으로 결정됐으며 domain·feature 사이드바와 타임라인·상세 작업 영역을 쓴다. 전체 모델·상호작용은 planning.md를 적용한다.

결정과 미결정 범위

결정 범위는 여섯 레이블·순서, 외부연동 일곱 분류, 문서 사이드바·읽기 발견 형태, planning.md의 수락 계획과 클라우드 도메인 연결이다. 클라우드 구현만으로 새 UI 제어·미결정 탐색이 승인되지 않는다.

다음은 Human 소유 미결정이다.

  • 에이전트·로그·테스트 사이드바 구조·상세 역량.
  • 개요 내용.
  • 원본 실시간 출처·질의 연결.
  • 클라우드 수집 계약을 넘는 추가 동기화 UI 트리거·상태 표시.
  • 인증 Document 계약을 넘는 추가 메타데이터 편집 UI.
  • 소유자 근거 투영을 넘는 외부연동 분류 탐색·자식 출처·생명주기 제어.

정의·연결 대기로 표시한다. 계층·기록·지표·제어·계정·연결 건강·역량을 발명하지 않는다.

권위 경계

Workspace는 소유자 근거 상태·승인 제어를 연결하며 정식 소유자가 되지 않는다. Agent는 로컬 실행·그래프·영수증, 클라우드는 공유 보고·검색, Document는 문서, Gather는 외부 동기화, Tool은 논리 외부 도구·연결 생명주기를 소유하고 공급자는 권위를 유지한다. 기존 로컬 발견 디렉터리·유틸리티는 Activity나 그 아래 중첩을 승인하지 않는다.

Workspace 인터페이스

Human 관제탑

  • 개발자에게 익숙한 VS Code 형태 셸을 쓰며 주요 영역 이름은 정확히 작업 표시줄·기본 사이드바·작업 영역이다.
  • 주 공간 관계는 작업 표시줄(Activity Bar) -> 기본 사이드바(Primary Sidebar) -> 작업 영역(Workspace area)이다.
  • Human 탐색·제어를 위한 프로젝트 상태를 표시하며 현재·미래 투영 상태의 정식 저장소·실행자가 되지 않는다.

공통 배치·상호작용·시각 토큰은 선택 MCP 런타임의 정식 static/에 둔다. 작업 표시줄 최상위 한국어 항목은 정확히 다음 순서다.

  1. 일정
  2. 에이전트
  3. 문서
  4. 외부연동
  5. 로그
  6. 테스트
  • 각 한국어 레이블을 장식 인라인 SVG 아래 보이는 글로 표시한다.
  • 지원하는 좁은 화면에서도 레이블을 남기며 아이콘 전용으로 축소하지 않는다.

다른 최상위 Activity는 허용하지 않는다. 별도 Explorer·File Explorer, Planning·Specification, Project Skills, 개요·대시보드, Roadmap·별칭 버튼을 추가하지 않는다.

  • 외부연동은 data-activity="external-integrations"의 네 번째 일반 Activity이며 하단 유틸리티·덧씌운 화면이 아니다.
  • 다른 Activity와 같은 상호작용으로 대응 사이드바·작업 영역을 선택한다.
  • 샘플 연동 없이 정직한 외부연동 상태 연결 대기로 시작한다.
  • 외부연동 사이드바는 웹·리서치, 문서·파일, 메일·메시지, 일정·회의, 지식·업무관리, 개발·운영, 데이터·비즈니스 순서의 정확히 일곱 분류 행을 표시한다.
  • 분류 탐색·자식 출처가 명시 결정될 때까지 의미 목록·보이는 글만 쓰고 버튼·링크·선택 상태·펼침 제어·발명한 개수는 두지 않는다.
  • 지원 사이드바 크기 조정 범위 전체에서 읽을 수 있어야 한다.
  • 문서 사이드바의 간결한 그룹 제목 높이·서체·레이블 안쪽 여백·배경·구분선 간격과 맞춘다.
  • 중복 본문 제목을 넣지 않는다. 정적 행이므로 펼침 아이콘 자리를 예약·표시하지 않는다.
  • 분류는 작업 목적 기준이다.
  • 공급자·계정·방법·상태·권한 범위·마지막 동기화 시각은 미래 소유자 근거 연동 항목의 속성이며 분류 축이 아니다.
  • Activity 화면은 읽기 투영 경계다.
  • 향후 소유자 기반 로더를 위해 window.agentFactoryWorkspace.externalIntegrations.replaceItems(items)를 제공한다.
  • 각 항목은 비어 있지 않은 안정 integrationIdentity를 가진 객체다. 선택 provider·account·method·status는 평문으로 표시하고 중복 ID는 실패 처리한다.
  • 빈 어댑터 결과는 대기 상태로 돌린다.
  • 개인 계정을 고정하거나 설치·연결·건강을 추론하거나 비밀을 노출하지 않는다. 권위 공급자·생명주기 경로 구현 전 연결·해제 제어를 추가하지 않는다.
  • 외부연동은 플러그인·커넥터·MCP 서버·직접 OAuth/API·로컬 마운트 또는 동기화·서비스 계정·외부 문서 URL·수동 가져오기를 포괄하는 Human 이름이다.
  • 커넥터는 한 방법일 뿐이다.
  • Workspace는 투영·상호작용만 소유하고 Tool 및 실제 호스트·플러그인·MCP 서버·공급자는 생명주기 권위를 유지한다.
  • 작업 표시줄 항목 하나에 사이드바 화면 하나·주 작업 화면 하나가 대응한다.
  • 문서 사이드바에는 원본 문서·가공 문서·명세 문서 순서의 두드러진 독립 접기 탐색기형 그룹을 둔다.
  • 원본은 개요·문서검색을 제공하며 검색은 상단 탭 없는 간결한 의미 표를 선택한다.
  • 접근 가능한 의미 표를 사용한다. 플러그인은 브라우저 라이브러리를 배포하지 않는다. 풍부한 정렬·크기 조정·검색·필터는 MCP 구현·의존성 정책 소유다.

  • 따라서 브라우저는 샘플 없이 데이터 연결 대기로 시작하고 미래 소유자 로더용 window.agentFactoryWorkspace.originalSearch.replaceRows(rows)만 제공한다.
  • 행은 classification, provider, tags, name, extension, modifiedAt, sourceUrl, 안정 sourceIdentity를 갖는다.
  • 위험 URL 스킴은 링크하지 않고 외부 HTTP(S)는 적절한 opener·referrer 격리를 적용한다.
  • 전역 검색 입력은 여섯 표시 필드에 매칭할 리터럴 글로만 취급한다.
  • 로컬 카탈로그 CLI로 연결하지 않고 명시 구현된 클라우드 소유자 연동만 사용한다.
  • 일정 사이드바·상세 계획은 planning.md를 따른다.
  • 원본 개요·에이전트·로그·테스트 사이드바와 상세 역량은 Human 소유 미결정이며 그렇게 표시한다.
  • 기존 서버·발견 유틸리티는 결정 문서 형태 밖의 Activity·데이터 연동을 승인하지 않는다.
  • 이 미해결 경계는 확인된 테넌트 가공 문서 발견에는 더 이상 적용되지 않는다.
  • 원본 개요는 편집 헤더 없이 간결한 작업 영역 안쪽 여백을 직접 쓴다.
  • 문서 사이드바 마지막 명세 그룹의 목록·상태 아래 끝 구분선은 없애고 세 그룹 사이 구분선은 유지한다.
  • 이 장식 결정은 개요 내용을 결정하지 않는다.
  • 모든 사용자 아이콘은 실제 SVG다.
  • 개요·탐색기 장식 SVG는 접근성 트리에서 제외하고 보이는 한국어가 상호작용 요소의 접근 이름이다.

MCP 런타임과 게시

선택 Agent Factory MCP 애플리케이션이 플러그인 Skill 계약과 별도로 Workspace 구현을 소유한다.

  • 정식 자산은 MCP static/에 해당 의존성 정책으로 관리한다.
  • FastAPI는 /workspace/의 Human 셸과 /api/ 아래 테넌트 자원을 제공한다.
  • 같은 애플리케이션이 /mcp 전송을 제공한다.
  • 인증 요청으로 조직·Workspace를 확인하며 프로젝트에 브라우저 자산을 복사하지 않는다.
  • PostgreSQL은 테넌트 메타데이터·pgvector 색인, S3 호환 저장소는 불변 문서 리비전 본문을 소유한다.

  • 런타임 소스·배포 어댑터·테스트는 MCP 저장소 소유이며 skills/workspace/·프로젝트 루트에 재생성하지 않는다.

시작·재시작·런타임 환경은 클라우드 자체 배포 계약 소유다. Skill 작성은 배포·재시작 권한이 아니며 플러그인은 로컬 Workspace 실행기를 제공하지 않는다.

  • MCP HTTP 호스트는 허용 루트의 성공 정적 파일 응답마다 Cache-Control: no-store를 붙인다.
  • /workspace/ 셸·정식 로컬 CSS·JavaScript에 적용한다.
  • 이 정적 신선도 정책을 JSON API·리디렉션에 확대하지 않는다.
  • X-Content-Type-Options: nosniff, 경로 포함·심볼릭 링크 거부·탈출 방어를 함께 유지한다.
  • 서버 변경은 애플리케이션 승인 배포 흐름으로 적용한다. 정적 신선도 자체는 재시작을 승인하거나 배포 갱신을 주장하지 않는다.

Workspace UI는 투영·제어 화면이다. 보인다고 수락·건강·완료·권위가 성립하지 않는다. Agent 세션·원본과 가공 및 명세·Project Skill·Human 결정은 소유 저장소·규칙을 유지한다.

  • 클라우드는 새 문서 색인·검색·공유 보고·연결과 수집 설정을 소유한다. Workspace는 인증 소유자 상태를 투영하고 프로젝트 db.sqlite를 초기화·질의하지 않는다.
  • 로컬 exec·loop·세션·실행·영수증·발신함·복구는 로컬 권위를 유지한다. 클라우드 보고·오래된 관찰은 그래프 시작·완료·취소·진행이 아니다.
  • 계획 작업·백그라운드 작업·로컬 보고는 별개 도메인이다. planning.md·제공 소유 스키마를 적용하고 교차 완료를 추론하지 않는다.
  • 확인된 인증 클라우드 연결·현재 스키마와 안내를 쓴다. 역량·계정·범위 누락은 사용 불가·미해결이며 실제 연결을 발명하거나 옛 스크립트로 대체하지 않는다.
  • Git 소유 Skill·한국어 HTML 게시 소스는 검토 저장소·커밋·목록 스냅샷에 결속된다. 클라우드는 수락 게시 리비전을 소유하고 Workspace는 두 번째 편집 진실이 아니다.
  • 기존 출처·설정·카탈로그는 목록화·독립 백업·가져오기 검증까지 보존한다. 코드 폐기는 삭제 권한이 아니다.
  • 실제 테넌트·계정·자격증명 권위·미해결 제어·배포와 전환은 명시 소유 결정이다. 이 계약은 등록·운영 설정·1–13단계 완료를 주장하지 않는다.

개발 계획: 2026-09-05 수락

Human은 기존 작업 표시줄 -> 기본 사이드바 -> 작업 영역 셸의 일정 Activity 구현을 수락했다. 개발 계획만 해결하며 다른 Activity·백그라운드 작업 예약은 바꾸지 않는다. 선택 MCP가 테넌트 PostgreSQL 계획 기록을 소유한다.

모델과 작업

  • 구별되는 세 수준은 기능 도메인(domain) -> 사용자 기능(feature) -> 구현 이슈(issue)다. 부모는 같은 Workspace에 있어야 하며 수준을 건너뛸 수 없다. Domain에는 부모가 없고 생성 후 kind·parent는 불변이다.
  • 모든 수준에 이름·설명이 있다. Feature는 인수 기준·담당 레이블·pending/active/done 상태·선택 막힘 이유·선택 시작과 목표일을 갖는다. Issue는 담당 레이블·상태·막힘 이유·선택 목표일을 갖는다. 담당은 계획 레이블이며 Agent 실행·권한 부여가 아니다.
  • Domain 시작일·목표일은 각각 직접 지정한 값을 우선하고 비어 있는 날짜만 알려진 feature 시작의 최솟값·목표의 최댓값으로 집계한다. 빈 domain은 pending, 모든 feature done이면 done, active 또는 부분 완료 집합이면 active, 나머지는 pending이다. 없는 날짜는 미지정으로 보이며 추정하지 않는다.
  • Feature 기간·상태는 명시 관리한다. Issue 완료 수는 시간 기반 진도·자동 feature 완료가 아니다.
  • Workspace 계획에는 선택 출시 목표일도 있다.
  • 조회·생성·갱신·삭제는 테넌트 범위·권한 확인 API다. 읽기는 workspace.read, 쓰기는 workspace.manage·세션 CSRF가 필요하다. 리비전으로 묵시 덮어쓰기를 막고 계층 동시 편집은 Workspace 안에서 직렬화한다. 자식이 있는 부모는 삭제할 수 없다.
  • PostgreSQL plan_items·plan_settings가 저장을 소유하며 자동 예약·작업과 별개다. 프로젝트 로컬 계획 파일·브라우저 저장소가 업무 상태를 소유하지 않는다.

사이드바와 작업 영역

  • 사이드바는 고정 전체 일정 뒤 접을 수 있는 domain·feature다. 상태 SVG·이름·선택 강조를 제공하고 긴 이름은 생략하되 전체 title을 남긴다. 키보드 탐색을 유지한다. 새로고침·domain 생성을 제공하며 자식 생성은 선택 부모 화면에 둔다. Issue는 탐색 트리에 없다.
  • 전체 계획은 domain별 feature 타임라인이며 한 행에 feature 하나, 고정 이름 열·날짜 헤더를 둔다. 기본 주·대안 달력 월, 오늘·전체 맞춤·오늘 선·선택 출시 목표 표시를 제공한다. 날짜 누락도 행을 남기고 부분·미지정 기간을 명시한다. 클릭은 상세를 열고 복귀는 가로 위치를 유지한다.
  • Domain은 직접 지정·집계 기간과 파생 상태·설명 및 feature 표의 상태·기간·issue 완료 수를 표시한다.
  • Feature는 기간·상태·담당·인수 기준·설명·막힘 이유를 편집하고 issue 표에 이름·담당·상태·선택 목표를 둔다. 행 확장으로 설명·속성을 인라인 편집한다. 이동·다른 행 열기에도 초안을 유지하고 저장 성공 시 해당 초안을 지운다.
  • 지난 미완료 목표는 기한 초과, 막힘 항목은 막힘·이유를 표시한다. 알려진 feature 기간 밖 issue 목표는 상위 작업 기간 밖을 표시하고 feature를 의도적으로 편집할 수 있게 하되 자동 조정하지 않는다.
  • 편집은 명시 저장·취소, 삭제는 확인, 비어 있지 않은 부모는 거부한다. 리비전 충돌은 입력을 보존하고 취소+새로고침으로 최신 상태를 받도록 설명한다. 모달 취소는 그 모달 초안을 버린다.
  • 화면은 서버 스냅샷을 공유하고 저장 후 재로딩한다. 다른 Workspace·이전 로딩의 오래된 요청이 현재 데이터를 덮지 못한다. Workspace 전환은 선택·초안·이전 테넌트 내용을 지운다.
  • 정직한 로딩·빈·오류·재시도, viewer 읽기 화면, 보이는 포커스·의미 폼과 표·SVG가 필요하다.
  • 최초 구현은 클릭 날짜 편집이다. 의존선·드래그 일정·추가 대시보드·필수 issue 날짜는 요구하지 않는다.

런타임 계약

MCP 파일은 app/modules/planning/, app/router/planning.py, app/db/migrations/versions/0013_development_planning.py, static/js/planning.js, static/css/planning.css, 기존 template/workspace/index.html 셸이다. API 기준은 /api/organizations/{organization_id}/workspaces/{workspace_id}/plan이다. GET은 평면 유형 항목·파생 domain 필드·설정·can_edit를 반환한다. POST /items는 생성, PUT /items/{id}는 리비전과 편집 필드 교체, DELETE /items/{id}?revision=N은 리프 삭제, PUT /settings는 리비전과 launch_date 갱신이며 최초 생성 전 리비전은 0이다. Verification은 실제 DB 저장·권한·CSRF·RLS·계층과 날짜 거부·동시 쓰기 및 브라우저 탐색·렌더링·편집·테넌트 전환·오류 복구를 다뤄야 한다.

새로고침과 작업 추가는 기본 사이드바 헤더 오른쪽의 SVG 아이콘 버튼으로 제공한다. 일정 선택 시에만 표시하며 추가는 편집 권한이 있을 때 제공한다. 본문에는 전체 일정과 도메인/기능 탐색 트리만 둔다.

공통 일정 용어: 2026-09-05 수락

모든 수준의 공통 사용자 이름은 작업(Task)이다. 사이드바 헤더는 작업 추가, 선택 부모 아래 생성은 하위 작업 추가, 이름 필드·표와 타임라인 이름 열은 작업 이름, 자식 절은 하위 작업이다. 파생 합계는 하위 작업에서 집계, 범위 밖 목표는 상위 작업 기간 밖과 상위 작업 기간 조정으로 설명한다. 빈 상태·대화상자·접근성 이름·도움말·검증 오류에도 일반 용어를 쓴다.

domain/feature/issue 저장 종류·세 수준 부모 제약·완료 기준·날짜 규칙·issue 상세 편집은 그대로다. 요약 작업·하위 작업은 관계 설명이며 세 새 고정 유형명이 아니다. 임의 깊이 WBS나 기록 이름 변경을 구현하지 않는다.

일정 헤더 제어는 사이드바 내용 폭 안에 둔다. 현재 헤더 패딩을 넘거나 가로 스크롤을 만드는 음수 끝 여백을 쓰지 않는다.

외부 AI 일정 가져오기: 2026-09-05 수락

사용자가 선택한 외부 AI가 자체 파일 도구·연결·MCP로 Excel·Google Sheets·Notion·Jira를 읽고 해석해 버전 1 공통 제안을 제출한다. 계획 가져오기 역량은 모델·출처 서비스 연결을 호스팅하지 않으며 별도 승인 클라우드 Gather 연동은 다른 도메인이다. 사용자 요청 일방향 가져오기이며 자동 동기화가 아니다.

planning_schema, planning_read, planning_import_preview, planning_import_apply 및 agent-factory://planning/import-guide를 제공한다. 세 수준·필드 제약을 보존한다. 항목에는 안정 공급자·문서·행 ID, 부모 참조, 전체 편집 필드, 원래 값·위치, 이유 있는 정정·미해결 질문을 둔다. 선언 읽기 범위는 완전해야 하며 없는 날짜는 null, 미해결 질문은 적용을 막는다. 이름 기반 자동 병합·가져온 삭제는 없다.

미리보기·출처 연결은 테넌트 PostgreSQL plan_imports·plan_source_links(0016)에 저장한다. 미리보기는 계획 항목을 바꾸지 않는다. 전체 일정 → 가져오기는 최신 50개 미리보기·결과와 출처·읽기 범위·계층·추가와 갱신 및 동일 행·전후 값·원래 값·정정 이유·오류·경고를 표시한다. 모든 가져온 텍스트를 이스케이프한다. 적용 전에 사용자가 조사·확인하며 viewer는 읽기만 가능하고 제출·적용하지 못한다. 헤더 새로고침·추가·탐색은 가로 넘침 없이 간결하게 유지한다. Workspace 전환은 대기 화면 상태·오래된 응답을 버리고 로딩·오류는 재시도를 제공한다.

REST·MCP는 같은 소유 검증을 사용한다. MCP 읽기는 schedule:read와 workspace.read, 쓰기는 schedule:write와 workspace.manage가 필요하며 브라우저는 CSRF를 사용한다. 새 editor MCP 연결에는 schedule:write를 주지만 기존 토큰을 묵시 승격하지 않는다. 범위가 없는 기존 토큰은 MCP 제출용 새 연결이 필요하며 브라우저 적용은 현재 사용자 권한을 쓴다. 미리보기 ID는 테넌트 범위다.

같은 요청 키·동일 내용은 같은 영속 미리보기를 반환하고 다른 내용은 실패한다. 적용에는 정확한 미리보기 해시·명시 경고 확인이 필요하며 적용 재시도는 같은 결과다. Workspace 잠금이 쓰기를 직렬화한다. 중간 항목 리비전·식별자·출처 연결 변경은 대기 미리보기를 무효화한다. 모든 계획 행·출처 연결은 원자 커밋한다. 기존 kind·parent는 바뀌지 않는다. 안정 출처 ID로 반복 가져오기를 같은 항목에 연결하고 existing_id는 미연결 출처를 현재 항목에 명시 결속한다. 제안은 누락 필드 기본값까지 모든 편집 필드를 교체하므로 미리보기는 전체 변경을 보여야 한다. 제안당 최대 500개이며 더 큰 범위는 순차 배치·안정 부모 참조를 쓴다. 전체 수집 완전성·의미 진실은 외부 호출자 주장이지 스키마 검증이 독립 증명할 수 있는 것이 아니다.

런타임 docs/planning-import.md에는 네 출처 예시·연결과 범위·매핑과 불확실성 규칙·미리보기와 적용 순서·멱등성과 충돌 복구가 있다. 런타임 이미지에 포함한다. Verification은 결정 계약·실제 PostgreSQL 이관 주기·RBAC와 CSRF와 RLS·재시도와 동시성과 충돌·실제 MCP 호출·브라우저 검토와 적용·신뢰하지 않는 텍스트 렌더링을 다룬다.

최상위 선택 날짜와 필수 표시: 2026-09-06 수락

최상위 시작일·목표일은 독립적으로 선택 입력한다. 직접 값이 우선하며 비어 있는 쪽만 하위 작업에서 집계하고, 둘 다 없으면 미정이다. 상태는 계속 집계한다. GET 스냅샷의 start_date/target_date는 표시 날짜이며 configured_start_date/configured_target_date가 저장된 직접 값이다. 날짜별 출처는 start_date_source/target_date_source의 explicit·derived·unspecified로 구분하고, period_conflict로 기간 충돌을 알린다. 편집·가져오기에서 기존 입력을 유지하려면 configured 값을 사용하여 집계 날짜가 저장으로 고정되지 않게 한다.

직접 지정한 두 날짜의 역전은 거부한다. 직접 날짜와 집계 날짜가 섞여 역전되면 값을 변경하거나 추측하지 않고 기간 확인 경고를 표시한다. 상세와 전체 일정 그룹에 날짜별 직접 지정·하위 작업에서 집계·미정을 표시한다. 하위 작업 없는 최상위도 전체 일정에 남고 전체 맞춤에 최상위 날짜를 포함한다.

하위 작업의 알려진 날짜가 최상위 표시 기간 밖이거나 이슈 목표가 중간 작업 기간 밖이면 경고와 상위 작업 편집을 제공한다. 저장을 막거나 날짜를 자동 조정하지 않는다. 가져오기 미리보기도 반영 후 계층의 기간 이탈·충돌을 검토 경고로 반환한다.

작업 이름에는 *와 HTML required를 적용하고 폼에서 * 필수 항목을 설명한다. 날짜 등 선택 항목에는 별도 선택 문구나 별표를 붙이지 않는다. API·MCP 안내, 패키지 안내 문서, 검사와 Human·AI 명세를 일치시킨다.

타임라인 위치·너비는 서버의 style-src self 보안 정책 아래에서도 적용되어야 한다. HTML style 속성 대신 개별 CSSOM 속성으로 수치 위치·너비를 지정한다. 날짜 눈금·오늘 설명은 간결한 헤더에 두고 출시 날짜는 화면 요약에 표시하며 본문 기준선이 작업 기간·출처 설명을 가리지 않게 한다. 브라우저 검사도 같은 보안 정책에서 실제 배치 치수를 확인한다.

전체 일정 디자인: 2026-09-06 수락

GitHub Projects 로드맵, Notion의 표와 타임라인 분리, Jira의 상하위 일정 막대를 참고한다. 왼쪽 고정 작업 열은 넓은 화면 280px·좁은 화면 220px로 두고 이름·상태와 기간을 두 줄로 표시한다. 하위 작업은 들여쓰기한다. 날짜가 없으면 왼쪽에 기간 미정만 쓰며 오른쪽 날짜 영역은 비운다. 최상위 출처는 직접 지정·집계·직접 지정·집계 조합 배지로 간결하게 표시하고 title에 날짜별 설명을 제공한다. 상세 화면에는 날짜별 출처를 계속 표시한다.
