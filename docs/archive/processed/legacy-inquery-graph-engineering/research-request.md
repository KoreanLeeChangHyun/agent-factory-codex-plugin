# 조사 요청: 그래프 엔지니어링 종합 리서치

사용자 요청: "그래프 엔지니어링에 대한 정보를 웹에서 모든 데이터를 검색하고 정리하고 취합하세요"

## 목적

2026-08-28 기준, 실제 시스템을 설계·구축·운영하는 의미의 **그래프 엔지니어링(Graph Engineering)** 을 한국어로 폭넓고 깊게 조사한다. 인터넷 전체의 문자 그대로의 전수 수집은 불가능하므로, 검색 범위·선정 기준·한계를 명시하고 재현 가능한 종합 리서치를 만든다.

## 조사 범위

- 용어 정의와 인접 분야(그래프 이론, 데이터 엔지니어링, 지식 그래프, 그래프 분석, GraphRAG, GNN)의 경계
- 그래프 데이터 모델: property graph, RDF/semantic graph, hypergraph 및 주요 트레이드오프
- 저장·인덱싱·분산 아키텍처, OLTP/OLAP/streaming 그래프 처리
- 표준과 쿼리 언어: SQL/PGQ, GQL, Cypher/OpenCypher, Gremlin, SPARQL/RDF/OWL/SHACL 등
- 그래프 알고리즘과 분석, GNN/graph ML, vector+graph 하이브리드, GraphRAG
- 수집/ETL/ELT, entity resolution, ontology/schema, 데이터 품질, provenance, temporal graph
- 성능, 확장성, 벤치마크, 테스트, 관측성, 보안, 개인정보, 거버넌스
- 대표 OSS/상용 생태계와 선택 기준. 단순 마케팅 나열이 아니라 공식 문서로 기능을 확인하고 범주화
- 실무 아키텍처 패턴, 안티패턴, 팀 역할/역량, 도입 로드맵, 의사결정 프레임워크
- 주요 연구·표준화 동향 및 아직 해결되지 않은 문제

## 조사 방법과 출처 규칙

- 웹 검색을 실제로 수행한다. 최신성에 민감한 내용은 2026-08-28 기준으로 확인한다.
- 표준기관(ISO/IEC, W3C 등), 공식 제품/프로젝트 문서, 원 논문·학회 자료, 공식 벤치마크를 우선한다.
- 기술적 주장에는 가능한 한 바로 옆에 클릭 가능한 원문 URL을 붙인다.
- 검색 결과 페이지, SEO 요약글, 출처 불명의 집계는 근거로 삼지 않는다.
- 제품 비교는 검증 가능한 기능과 라이선스/운영 모델을 구분하며, 확인되지 않은 시장점유율·성능 우열을 단정하지 않는다.
- 서로 다른 정의나 논쟁이 있으면 합치하지 말고 상충 관계를 기록한다.
- 직접 인용은 최소화하고 요약한다.

## 결과물

1. 상세 조사 문서를 `.agent-factory/inquery/graph-engineering/report.md`에 작성한다.
2. 별도의 `.agent-factory/inquery/graph-engineering/sources.md`에 출처를 범주별로 정리한다. 각 항목은 제목, 기관/저자, 날짜(확인 가능할 때), URL, 어떤 주장에 사용했는지 포함한다.
3. `report.md`에는 최소한 다음을 포함한다:
   - 10문장 이내 핵심 요약
   - 범위와 조사 방법 및 '모든 데이터'의 현실적 한계
   - 분야 지도/분류 체계
   - 핵심 기술 상세
   - 표준/언어/도구 비교표
   - end-to-end 수명주기와 참조 아키텍처
   - 사용 사례별 적합성/부적합성
   - 도입 체크리스트와 단계별 로드맵
   - 리스크·상충 근거·미해결 쟁점
   - 결론과 후속 조사 제안
4. 관리 런의 결과 파일에는 조사 경계, 핵심 결론, 워크스페이스 파일 경로, 한계, 후속 조사만 간결히 요약한다.

이것은 임시 Inquiry 자료이며 Specification이나 Project Skill로 승격하지 않는다. 제품 변경, 테스트, 외부 쓰기 작업은 수행하지 않는다.
